# ЕГЭ Профиль 2027

Неофициальный PWA-тренажёр первой части ЕГЭ по математике профильного уровня с адаптивным интерфейсом. Язык интерфейса и учебных материалов: русский.

## Состояние проекта

Текущее рабочее дерево расширяет гостевое ядро по [утверждённому дизайну завершения](docs/superpowers/specs/2026-11-05-completion-design.md). Исходное [`technical-spec.md`](technical-spec.md) не сокращено. Ни наличие кода, ни промежуточные тесты не означают приёмку полной версии.

| Диагностика и пробник | Подготовка всех 13 условий до старта, серверный дедлайн пробника, явная передача управления между устройствами, отдельные неизменяемые серверный и локальный результаты. |
| Обучение и закрепление | Версионированный учёт самостоятельных ответов, интервалы 1/3/7/14/30 дней, освоение, смешанный подбор, план, ошибки, избранное и выбранные учеником причины ошибок. |

| Эксплуатация | Обработчик дедлайнов, диагностические счётчики, инструменты копирования/восстановления, read-only статус/план удаления и изолированный нагрузочный сценарий; PostgreSQL CI-gate подготовлен. |

- Экзаменационный профиль хранится в данных. № 1–13, максимум первой части 13 первичных баллов. Статус профиля: **«Проект»**.
- Профиль перенесён из ТЗ от 5 ноября 2026 года. Основные числа и проектный статус технически сверены с ФИПИ: [`docs/source-verification.md`](docs/source-verification.md). Полная независимая методическая сверка ещё требуется.
- По умолчанию используется `backend/content/course/`: **845 задач = 780 новых + 65 исходных; 99 уроков = 78 новых экзаменационных + 8 базовых + 13 исходных**. Все задачи — `demo`, рецензенты не заполнены. Численные минимумы банка выполнены технически, но это не 650 независимо проверенных задач. ## Локальный запуск без Docker

Нужны Node.js 24, npm и Python 3.13. Python-зависимости устанавливаются только в `backend/.venv`.

### Windows PowerShell

В первом терминале:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:ALLOW_DEMO_CONTENT = 'true'
$env:COOKIE_SECURE = 'false'
$env:ALLOWED_ORIGINS = 'http://127.0.0.1:5173'
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Если `python` в PATH открывает Microsoft Store, используйте полный путь к установленному Python 3.13 для команды создания окружения. Все последующие команды уже используют `.venv`.

Во втором терминале из корня проекта:

```powershell
cd frontend
npm ci --ignore-scripts
npm run dev -- --host 127.0.0.1 --port 5173
```

### Linux / macOS

Первый терминал:

```sh
cd backend
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
export ALLOW_DEMO_CONTENT=true
export COOKIE_SECURE=false
export ALLOWED_ORIGINS=http://127.0.0.1:5173
.venv/bin/python -m alembic upgrade head
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Второй терминал из корня проекта:

```sh
cd frontend
npm ci --ignore-scripts
npm run dev -- --host 127.0.0.1 --port 5173
```

Открыть **http://127.0.0.1:5173**. API проксируется Vite по `/api`. Документация FastAPI: **http://127.0.0.1:8000/docs**. Не меняйте origin браузера на `localhost` без соответствующей настройки `ALLOWED_ORIGINS`.

По умолчанию загружается расширенный курс; `CONTENT_DIR` позволяет явно выбрать другой пакет. При `ALLOW_DEMO_CONTENT=false` выдача непроверенного демонстрационного банка закрыта. Это намеренный безопасный отказ, а не неисправность. Не включайте email-вход фиктивными согласиями или тестовой почтовой доставкой: подготовка описана в [`docs/accounts.md`](docs/accounts.md).

## Docker Compose

```sh
cp .env.example .env
```

Заполнить `POSTGRES_PASSWORD` случайным паролем из 64 шестнадцатеричных символов. Затем:

```sh
docker compose up --build -d
```

Открыть **http://127.0.0.1:8080**. База и API не открывают внешних портов. Исходные образы закреплены digest. Подробнее: [`docs/deployment.md`](docs/deployment.md).

**Не удаляйте том `postgres_data` без резервной копии и явного согласия на потерю истории.** Остановить сервисы без удаления данных можно командой `docker compose stop`.

## Проверки

Windows, из `backend/`:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pip check
```

Linux / macOS, из `backend/`:

```sh
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check .
.venv/bin/python -m pip check
```

Из `frontend/`:

```sh
npx playwright install chromium
npm run lint
npm test
npm run build
npm run test:e2e
```

Сквозные тесты самостоятельно запускают API, выполняют production-сборку и поднимают `vite preview` на портах 8000 и 5173. Проверяется настоящий service worker, а не dev-режим Vite. Перед запуском закройте проверочные вкладки и остановите вручную запущенные серверы на этих портах. Для E2E используется отдельная случайно названная временная SQLite-база; пользовательская локальная база не очищается.

Не пересобирайте `dist` под открытой вкладкой работающего preview: смена хешей может сделать старый ленивый модуль недоступным. Порядок безопасного локального обновления и ограничения PWA описаны в [`docs/deployment.md`](docs/deployment.md#обновление-клиента-и-pwa).

PNG-иконки PWA включены в исходники. После изменения `frontend/public/icon.svg` их можно пересоздать командой `npm run icons` из `frontend/` с установленным Chromium Playwright. Генератор сохраняет непрозрачный фон для системной маски; обычная сборка не требует браузера.

Workflow содержит проверки Python, клиента, браузера, Compose и отдельный `postgres-operations` для миграции заполненной БД, реального восстановления и нагрузки **500 пользователей / 30 RPS / 600 секунд**. Подготовленный job ещё не означает успешный запуск. Протоколы и ограничения: [`docs/operations.md`](docs/operations.md#9-проверка-артефакты-и-оставшиеся-границы), [`docs/acceptance-status.md`](docs/acceptance-status.md); итоговые доказательства на точном SHA добавляет координатор в [`docs/verification.md`](docs/verification.md).

## Правила ответа

- Допускаются целое число и конечная десятичная дробь, точка или запятая, обычный или математический минус.
- В учебной практике допускается равная дробь `a/b` с положительным знаменателем. В диагностике и пробнике дробь через `/` отклоняется как формат.
- Не допускаются `NaN`, `Infinity`, выражения, степени, знак плюс, единицы, разделители тысяч и внутренние пробелы.
- Пустое поле не равно нулю. Максимум исходного ввода: 64 символа.
- Ошибка формата не создаёт математическую попытку. Неверный первый ответ остаётся неверным даже после исправления.
- Подсказка или решение перед первым ответом отмечает помощь; просмотр теории не повышает статистику самостоятельных ответов.
- Повтор того же экземпляра, включая числовой alias другого seed, не создаёт новое самостоятельное достижение. В диагностике и пробнике итог считается по последнему ответу; первое числовое значение хранится отдельно.
- Обновление страницы восстанавливает сессию и черновик. Без сети серверная проверка и новая выдача недоступны; начатый пробник работает с заранее сохранёнными условиями. Локальный итог замораживается и после связи хранится отдельно от серверного, без скрытой перезаписи балла.
- Общая JSON-выгрузка версии `1` содержит практику, диагностику/пробники, обучение и минимальные данные аккаунта либо `account: null`; не включает токены, MFA-секреты и закрытые результаты. Некорректный архив отклоняется целиком, а не молча обрезается.
- Запрос удаления показывает срок, но сам по себе не означает исполненное удаление. Схема `0008` даёт терминальные отмены/квитанции и detached-аудит существующего транзакционного исполнителя `active_cloud_v1`; операционный статус/план остаётся read-only, без нового исполнителя и автоматического purge. Проверки удаления разрешены только на одноразовых данных, не на текущей пользовательской базе.
- Авторитетное стирание после восстановления не подтверждено: `restore_replay_available=false`. Opt-in capture/replay не заменяет окончательную версионную привязку под блокировкой и внешнее долговечное отображение исходных account/origin ID. Без них ввод восстановленной production-БД в эксплуатацию заблокирован; [границы копий и восстановления](docs/accounts.md#backup-and-restore-boundary) не снимаются квитанцией удаления.

## Структура

```text
backend/
  app/          Практика, accounts, assessments, learning, editor, generators, operations
  content/      Исходный регрессионный пакет и активный кандидатный course/
  migrations/   Миграции Alembic
  tests/        Числовые, контентные и интеграционные тесты
frontend/
  src/          Интерфейс, типы API и IndexedDB
  tests/        Проверка сохранения и учебных операций
  e2e/          Браузерные сценарии
infra/          nginx и примеры расписания резервных копий
scripts/        Контейнерный smoke и изолированные операционные проверки
docs/           Контракты, план, ограничения и протоколы
```

Архитектура расширения: [дизайн завершения](docs/superpowers/specs/2026-11-05-completion-design.md). Контракты: [исторический контракт первого этапа](docs/api-contract.md), [аккаунты](docs/accounts.md), [диагностика/пробник](docs/assessments-api.md), [обучение](docs/learning-api.md), [редактор](docs/editor.md), [runtime](docs/runtime-issuance.md). Актуальную схему текущего сервера генерирует локальный [OpenAPI](http://127.0.0.1:8000/openapi.json); текущие клиентские DTO находятся в [`frontend/src/api/types.ts`](frontend/src/api/types.ts), [`assessments/types.ts`](frontend/src/assessments/types.ts) и [`accounts/types.ts`](frontend/src/accounts/types.ts). Визуальный контракт: [`DESIGN.md`](DESIGN.md). Подсистемные протоколы относятся к указанным в них срезам; актуальную интеграцию и остаток требований фиксирует [матрица приёмки](docs/acceptance-status.md).

## Права и материалы

В банке используются собственные демонстрационные условия и объяснения, подготовленные с помощью ИИ. Внешние банки, рисунки и решения не копировались. ФИПИ указан как источник экзаменационной структуры, не как партнёр проекта. Правовое основание публикации и независимая предметная проверка должны быть подтверждены до публичной поставки. Лицензии сторонних библиотек перечислены в [`docs/dependencies.md`](docs/dependencies.md).

Репозиторий приватный. Открытая лицензия на проект без отдельного решения заказчика не назначена.
