## Состав и интерфейсы

- `backend/app/generators/__init__.py` — явный реестр и проверенная генерация.
- `backend/app/generators/build.py` — детерминированный выбор экземпляров,
  сборка в памяти, ограниченная запись и проверка актуальности файлов.
- `backend/content/course/` — каталог восьми выходных артефактов.
- `backend/tests/test_course.py` — центральные проверки контрактов, полного
  пакета, разнообразия математических данных и границ записи.

`FAMILIES` — кортеж из **78** записей `Family` в порядке
`geometry_probability` (29), `algebra_analysis` (25), `applied_finance` (24).
`FAMILY_BY_ID` — неизменяемое отображение этих записей.
`RUNTIME_FAMILIES` содержит ровно **26** семейств: по два на каждую позицию 1–13.

```python
from app.generators import generate, reproduce

task = generate("right-triangle-area", 4294967295, profile)
static_task = reproduce("vector-angle", 0, profile)
```

Обе функции возвращают `app.content.Task` и принимают переданный
`app.schemas.ProfileSource`. `generate(template_id, seed, profile)` разрешает
только runtime-семейства; `reproduce(template_id, seed, profile)` разрешает все
78 семейств для статической сборки и редакционного пересчёта.

Seed — строго `int` от 0 до `4294967295` включительно. Булевы значения, строки,
числа с плавающей точкой, дроби и выход за диапазон отклоняются до генерации.
Идентификатор выбирается из явного реестра. Профиль повторно проверяется после
выгрузки в словарь, включая изменения уже созданного экземпляра Pydantic.
Результат проходит `data_only`, схему `Task` и проверку привязки к семейству,
профилю, позиции, стабильному `slot_id`, навыкам и исходному seed.

ID экземпляра: `course-{family_id}-{seed}`; редакция задачи и версия шаблона —
`"1"`. У всех новых задач сохраняется `generation` с `template_id`,
`template_version` и `seed`, в том числе у статических семейств.

`build_course() -> dict[str, bytes]` собирает весь пакет в памяти. Он читает
три исходных JSON по явному пути `backend/content/`, вызывает актуальные
авторские модули и проверяет итог через `validate_content`. Сборка не зависит
от настроенного каталога приложения, часов, БД или глобального random state.

## Выбор десяти экземпляров

Для каждого семейства создаётся отдельный фиксированный пул:

1. Весь uint32-диапазон делится на **512 равных страт** шириной `8388608`.
2. В каждой страте выбирается seed со смещением из SHA-256 строки
   `stratified-v1:{family_id}:{stratum}`. Встроенный Python `hash()` не используется.
3. Добавляются обе границы диапазона, базовые `0..9` и явные переходы ветвей.
   Среди них касательная `17`, знаковый интеграл `51` и `68`, нулевая разность
   векторов `817`, нулевое скалярное произведение `74`, смена отношений
   пифагоровых троек и медленно меняющихся параметров прикладных задач.
4. Дубли seed удаляются с сохранением порядка. Каждый кандидат проходит
   проверенную генерацию; дубли видимого условия объединяются. Одинаковое
   условие с разными эталонами останавливает сборку.

Материализованная сборка обследует **40 848 пар «семейство, seed»**. Это объём
кандидатного пула; в итоговом расширении остаются ровно 780 выбранных задач.

Границы и переходные seed входят в пул кандидатов; они не обязаны попасть в
итоговую десятку. Сборщик последовательно выбирает кандидата по приоритетам:

1. новый **точный ответ**, сравниваемый через `Fraction`;
2. ещё не представленный знак ответа;
3. новая категориальная ветвь математической модели;
4. новые значения нормализованных математических признаков;
5. новая комбинация этих признаков;
6. ещё не представленный крупный участок uint32-диапазона.

При равенстве приоритетов побеждает первый кандидат. Число различных ответов
должно равняться `min(10, число ответов в пуле)`, а множество знаков — множеству
знаков в пуле. Нарушение останавливает сборку. Это максимум по обследованному
пулу; полный перебор всех `2**32` seed не выполняется.

Идентичность условия определяется нормализованными пробелами в тексте и
формуле, а также таблицей. ID, seed, ответ, решение, подсказки и декоративные
изменения рисунка не делают условие новым. В текущих шардах все необходимые
данные рисунков также опубликованы в тексте или таблице.

### Проверка математического разнообразия

Признаки вычисляются из публичных данных задачи, без восстановления параметров
из seed. Отдельные тесты самостоятельно вычисляют отношения, разности,
центрированные распределения, наклоны и ветви графиков:

- прямоугольные треугольники: пять отношений катета к гипотенузе;
- перемещения: пять отношений проекций и оба направления первой проекции;
- призмы: десять высот и десять отношений катетов основания;
- трапеции: десять высот и десять разностей оснований;
- среднее, дисперсия, CDF: шесть векторов вероятностных весов, разные разрывы
  между значениями и десять распределений после удаления общего сдвига;
- кусочно-линейная функция: десять моделей после удаления сдвигов по обеим осям;
- знак производной: разные ширины сегментов и все восемь амплитуд;
- прикладные модели: разные отношения сопротивлений, времена движения по реке,
  абсциссы гиперболы, оба направления параболы и роста показательной функции;
- максимум ломаной: внутренняя вершина, правая граница и равенство максимумов.

Манифест содержит `model_coverage`, `normalized_model_count`,
`candidate_model_count` и число доступных значений каждого признака в пуле.
Это диагностические признаки, а не универсальное доказательство неэквивалентности
всех задач. У семейства без выделенного дополнительного признака нормализованная
сигнатура одна. Чистые сдвиги и масштабы не объявляются новыми методами решения.

### Конечные области и повторения

Некоторые модели имеют меньше десяти возможных ответов; все десять условий
при этом различаются. В выбранном пуле полностью представлены:

| Семейство | Различных ответов |
| --- | ---: |
| `vector-angle` | 5 |
| `distribution-missing-probability` | 8 |
| `distribution-two-point-deviation` | 4 |
| `distribution-step-cdf` | 4 |
| `distribution-uniform-interval` | 6 |
| `logarithm-difference` | 3 |
| `derivative-positive-length` | 5 |
| `river-speed-system` | 4 |

У двухточечного отклонения четыре разных расстояния между точками; остальные
условия повторяют эти модели со сдвигом. У конуса отношение радиуса к высоте
фиксировано как `3:4`. Такие ограничения явно сохраняются в отчёте.

Разные seed могут давать один математический экземпляр. Регрессия показывает
это на `complement-quality`: seed `0` и `999` дают разные ID при одинаковых
условиях и ответе. Код выдачи и учёта самостоятельных попыток должен использовать
каноническую идентичность условия, а не считать новый seed новым свидетельством.
Интеграция такого учёта относится к сервисам координатора.

## Уроки, практика и базовый модуль

Сборщик получает актуальные тексты из `build_lessons(profile)` каждого шарда.
У всех 78 экзаменационных уроков `practice_task_ids` перепривязываются к трём
выбранным задачам того же семейства. Числовые данные разобранных примеров
исключаются из кандидатов практики; отдельные проверки сверяют опубликованные
данные примера и каждой ссылки. У трёх задач разные ответы и представлены
допустимые знаки семейства. Их ID разрешаются внутри итогового пакета.

Восемь уроков из `foundations.py` имеют `slot=0`, `slot_id=null`,
`kind="foundation"`, собственные базовые навыки и `related_slot_ids` со стабильными
ID экзаменационных позиций. Они добавляются в `prerequisite_ids` связанных
экзаменационных уроков как рекомендации. Схема ссылок проверяется на неизвестные
ID и циклы.

У всех пяти семейств с `plane-theorem-choice` начальная публичная `formula=null`;
материализация проверяет эту правку актуального геометрического шарда.
Подсказки и решение сохраняются в приватной задаче, а `public_task` исключает
ответ, происхождение генерации и готовую помощь.

## Артефакты и команды

Фиксированный список файлов в `backend/content/course/`:

```text
profile.json
lessons.json
tasks.json
legacy/profile.json
legacy/lessons.json
legacy/tasks.json
manifest.json
review-worksheet.md
```

`manifest.json` фиксирует версию алгоритма, числа записей, контрольные суммы
исходного пакета и пяти авторских модулей, выбранные seed, ответы, знаки,
математические признаки и ссылки на практику для каждого семейства. Суммы
модулей сверяются также в конце сборки: изменение файлов во время работы
останавливает сборку и требует нового процесса.

Команды из `D:\math_ege\backend`, существующее виртуальное окружение:

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m app.generators.build --write
.\.venv\Scripts\python.exe -B -X utf8 -m app.generators.build --check
.\.venv\Scripts\python.exe -B -X utf8 -m pytest tests/test_course.py -q -p no:cacheprovider
.\.venv\Scripts\python.exe -B -m ruff check --no-cache app/generators/__init__.py app/generators/build.py tests/test_course.py
```

`--write` сначала полностью собирает и валидирует пакет, затем проверяет все
пути назначения. Разрешены только восемь фиксированных артефактов в
`content/course`; произвольного `--output` нет. Символические ссылки, junctions
и файлы с несколькими жёсткими ссылками отклоняются до записи. Каждый файл
заменяется атомарно через staging-файл в том же каталоге. Атомарность относится
к отдельному файлу: авария между заменами может оставить смешанные версии,
которые обнаружит `--check`.

`--check` заново собирает пакет в памяти, сравнивает все байты и возвращает код 1
со списком отсутствующих или устаревших файлов. Он ничего не записывает.
Без явно выбранного режима CLI завершается с ошибкой аргументов.

Пакет имеет обычный контракт `load_content(Path("content/course"))`; разрешение
выдачи материала `demo` остаётся отдельным решением приложения. Список runtime
для выдачи и полный реестр для воспроизведения имеют разные назначения.

## Протокол проверки

Центральные тесты включают проверку всех 780 выбранных ответов и **1000 различных
seed каждого из 26 runtime-семейств**, с обеими границами uint32. Runtime-набор:
`0`, `4294967295` и `(i * 2654435761) & (2**32 - 1)` для `i=1..998`.
Каждая из 26 000 пар генерируется повторно для проверки детерминизма.

Ожидаемый ответ получается из публичного условия, таблицы и необходимых
координат через арифметические оракулы файлов `test_course_geometry.py`,
`test_course_algebra.py`, `test_course_applied.py`. Импорт этих функций
не означает повторного запуска полных наборов тестов шардов. Повтор генерации
не увеличивает число разных проверенных пар; число pytest-кейсов также
не равно числу seed, поскольку runtime-проверка группируется по семейству.

### Исправление центральной тестовой выборки

Первый полный прогон после материализации дал **4 failed, 307 passed in 145.47s**.
Причина всех четырёх отказов: fixture `samples` выбирала задачи только по
`family_id` и включала исходные пять задач у двух семейств с совпадающими ID.
Это давало 15 записей вместо десяти и `generation=None` у исходных записей.

Выборка исправлена в `tests/test_course.py`: новые снимки дополнительно
отбираются по наличию метаданных генерации. Точечный прогон проверки всех
выбранных семейств, геометрических моделей и манифеста дал
**80 passed, 231 deselected in 28.49s**. После него выполнен полный успешный
scoped-прогон, приведённый выше. Материализация и исходные записи прошли этот
прогон без дополнительных правок данных.

экзаменационного урока у каждого семейства. Для заполнения следует сделать
копию: воспроизводимая сборка всегда создаёт чистый лист.

Независимых человеческих рецензий, подтверждаемых этой сборкой, **0**.
Автоматическая проверка схем, арифметики и разнообразия не заполняет рецензента.
Перед предметной приёмкой требуются фактическая проверка условий, формул,
ограничений, решений, навыков и читабельности материала другим специалистом,
включая не менее десяти результатов каждого публикуемого runtime-шаблона.
