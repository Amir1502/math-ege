# Завершение программной части

Заказчик подтвердил 5 ноября 2026 года продолжение по шести подсистемам после `0627684`. Стек, приватность репозитория и запрет выдавать непроверенный контент за рецензированный сохраняются. Этот документ дополняет исходное `technical-spec.md`, не уменьшает его критерии приёмки.

## Архитектура

Развивается текущий React/FastAPI/PostgreSQL монолит. Существующие practice-таблицы и снимки не пересоздаются. Новые таблицы добавляются миграциями; destructive downgrade запрещён. Подсистемы имеют отдельные модели, DTO, сервисы, маршруты и тесты.

1. `accounts`: аккаунты, одноразовые ссылки, сессии доступа, согласия, роли, MFA, заявки удаления. Привязка гостевых владельцев к аккаунту сохраняет ID, ответы и исходные пространства ключей идемпотентности. Доступ сериализуется общей корневой записью владельца. Старый гостевой секрет после привязки не получает доступ к аккаунту. Локальные очереди и кэши разделяются по личности.
2. `assessments`: отдельная модель диагностики/пробника, без ослабления practice DTO. Подготовка 13 условий предшествует подтверждённому началу и установке дедлайна. Проверка срока выполняется при записи и независимым восстанавливаемым обработчиком. Второе устройство читает либо явно принимает управление с новой генерацией writer. Подсказки и результаты закрыты сервером, не только интерфейсом.
3. `learning`: проекция неизменяемых событий, повторения, освоение, подбор, избранное, причины ошибок и ежедневный план. Исходные попытки и итоги не переписываются. Объединение аккаунта дедуплицирует доказательства по экземплярам. Связь с текущим курсом строится по стабильным навыкам/позициям, а не совпадению номера.
4. `editor`: типизированный JSON, редакции, независимый рецензент, публикация только администратором с MFA, снятие, уведомления об исключении ошибочных результатов. Редактор не запускает загруженный код. Пакет проверяется до записи; публикация с ошибками блокируется.
5. `generators` и `content/course`: воспроизводимые точные математические модели, статический стартовый пакет, уроки и матрица. Минимум 650 экземпляров и 26 поддерживаемых генераторов; авторские материалы остаются в демонстрационном статусе до независимой предметной рецензии. Проверка 1000 seed не заменяет десять ручных проверок каждого шаблона.
6. Эксплуатация: сроки фоновых операций, диагностические метрики без персональных данных, резервное копирование/восстановление в отдельную новую базу, нагрузочный сценарий, регрессионные браузерные проверки и документы.

## Решения по пограничным сценариям

- В диагностике/пробнике оценка выставляется по последнему ответу. Первое введённое значение хранится отдельно как история редактирования, но не подменяет итоговую попытку.
- Незавершённая или некорректная строка остаётся черновиком; при дедлайне не превращается в допустимую числовую попытку. В результате она даёт ноль с отдельной пометкой формата/пропуска.
- При сетевом разрыве серверный снимок и присланный позже замороженный локальный снимок неизменяемы и показываются раздельно. Эталоны закрыты до получения локального завершения. В освоении участвует только один канонический серверный результат, после разрешения выдачи; локальный учебный пересчёт не создаёт второе достижение.
- Повтор локального завершения с тем же ключом и телом возвращает прежний результат, другое тело конфликтует. После локального завершения редактирование запрещено.
- Интервалы: 1, 3, 7, 14, 30 дней. Раннее решение не сдвигает интервал; ошибка/помощь сбрасывает его. Проверяется другой экземпляр той же пары навык/семейство.
- Авторизация email выключена без явного согласованного режима и почтовой настройки. Тестовая доставка писем доступна только в изолированных тестах, не через публичный API.
- Подтверждение пользователем запроса удаления не означает разрешения агенту удалять текущую пользовательскую базу. При проверках используются новые временные базы; существующие данные сохраняются.
- Схема рисунка содержит только ограниченные координаты, линии, окружности и подписи. Произвольный SVG/HTML не принимается. Ответы продолжают проверяться точной рациональной арифметикой.

## Проверка и внешние границы

Каждая подсистема получает регрессионные тесты: утечки результатов, чужой владелец, повтор запросов, гонки, перезапуск, серверное время, отказ сети, миграция заполненной базы. Проверяются старые 423 backend-, 41 frontend- и 16 браузерных тестов без ослабления прежних гарантий. Устаревшие проверки численности демобанка остаются тестами исходного пакета, расширенный пакет получает отдельные проверки.

Не подменяются программной реализацией: независимый методист, юридическое заключение, права на материалы, согласия несовершеннолетних, внешняя почтовая доставка, реальная публичная инфраструктура, реальные мобильные устройства и пилот. По каждому пункту приёмка фиксирует выполненную команду/артефакт либо оставшуюся границу.
